# AI Architecture: How the AI Is Used and What It Cannot Do

## The 4-Layer Data Taxonomy

Every output from Lahore+ is classified into one of four layers. This is not just a UI design choice — it is a **core architectural constraint**.

| Layer | Color | What It Means | Example |
|-------|-------|---------------|---------|
| **Observed Data** | Teal | Directly measured from instruments or public sources | PM2.5 reading: 185 µg/m³ at 3:15 PM |
| **Deterministic Inference** | Purple | Computed from observed data using explicit rules | Episode classified as "Severe" (≥3× baseline) |
| **AI Hypothesis** | Amber | Generated by the AI model, constrained by evidence | "Investigate NE quadrant (High confidence, 85%)" |
| **Human Verification** | Green | Confirmed or rejected by a field officer | Officer found active construction dust source |

## What the AI Does

The AI component in Lahore+ is a **constrained hypothesis generator**. Specifically:

### Inputs It Receives
- PM2.5 time series from the detected episode
- Wind speed and direction measurements
- Geographic coordinates of nearby monitoring stations
- Historical pattern data from similar past episodes
- Time of day and seasonal context

### What It Produces
- **Directional investigation hypotheses** (e.g., "NW quadrant", "NE sector")
- **Confidence levels** (High / Medium / Low) based on evidence strength
- **One-paragraph reasoning** explaining what evidence supports the hypothesis
- **Exposure direction estimates** for the map visualization

### How It Is Constrained
- It **cannot** identify specific polluters or facilities
- It **cannot** claim certainty — all outputs carry confidence levels
- Its reasoning must reference specific evidence (wind data, historical patterns)
- All its outputs are clearly labeled as **AI HYPOTHESIS** in the UI

## What the AI Cannot Do

1. **Cannot identify polluters**: It generates directional investigation hypotheses, not source attribution. "Investigate the NE quadrant" is different from "Factory X is polluting."

2. **Cannot claim 100% accuracy**: Every AI output includes a confidence level. Low confidence means the evidence is weak.

3. **Cannot replace human judgment**: The system recommends. Human officers decide. The AI's recommendation is one input into the investigation decision.

4. **Cannot access private data**: It works only with publicly available monitoring station data and weather data.

5. **Cannot learn in real-time**: The learning loop requires human verification input, which happens after field investigation (hours to days later).

## The Accountability Loop

```
Detect → Assemble → Hypothesize → Recommend → Human Reviews → Field Investigation → Record Results → Learn
```

The critical part of this loop is the **Record Results** step. Without human verification, the system cannot improve. With it, the system builds an evidence base showing how often its recommendations are useful.

## Technical Stack

- **Backend**: FastAPI (Python 3.11), SQLite WAL mode, raw sqlite3 (no ORM)
- **AI Model**: Phase 4 gradient-boosted models (XGBoost/LightGBM) for episode classification and feature engineering
- **Frontend**: React 19, Recharts, Leaflet (maps), Lucide icons
- **Data Sources**: OpenAQ API, Pakistan Meteorological Department, EPA Punjab monitoring stations
- **Authentication**: HMAC-SHA256 tokens with role-based access (citizen / officer / admin)
